# Staff Pulse Dashboard

Высокотехнологичный и производительный дашборд для мониторинга организационной структуры компании. Приложение позволяет в реальном времени отслеживать иерархическую структуру (дивизионы → отделы → команды), просматривать интерактивное дерево и анализировать сводные показатели по штату, бюджетам и эффективности.

---

## 🚀 Технологический стек

*   **Бэкенд:** Golang 1.26 (фреймворк Gin, драйвер PostgreSQL `lib/pq`, Gorilla WebSockets).
*   **Фронтенд:** React 19 (сборщик Vite 8, TypeScript 6, TanStack Query v5, Axios, SCSS Modules).
*   **База данных:** PostgreSQL (локальная или в Docker).

---

## 🛠️ Инструкция по локальному запуску

Приложение настроено на запуск в два простых шага и автоматически инициализирует базу данных.

### Предварительные требования:
1.  Убедитесь, что у вас установлен и запущен локальный **PostgreSQL**.
2.  Должна быть создана пустая база данных под названием **`test_task`** (пользователь `postgres`, пароль `1234`).

### Шаг 1: Запуск бэкенда (Go)
Зайдите в папку `backend` и запустите скомпилированный сервер (или соберите его вручную):
```bash
cd backend
# Запуск готового сервера:
./server

# Или ручной запуск через Go CLI:
go run cmd/server/main.go
```
*   **Что произойдет:** Сервер автоматически подключится к PostgreSQL, создаст таблицу `org_nodes` с индексами, сгенерирует **42 реалистичных узла** орг-структуры компании и запустит API на порту `8080`, а также WebSocket-сервер на `/ws`. В фоновом режиме запустится таймер, симулирующий изменения показателей команд каждые 5 секунд.

### Шаг 2: Запуск фронтенда (React)
В новой вкладке терминала зайдите в папку `client` и запустите dev-сервер:
```bash
cd client
# Установка зависимостей (уже выполнена, но на случай чистой среды):
npm install

# Запуск dev-сервера:
npm run dev
```
*   После запуска откройте в браузере адрес: **`http://localhost:5173`**

## 🧪 Запуск Юнит-тестов

Логика рекурсивного расчета суммарных бюджетов, headcount и средневзвешенной по людям эффективности покрыта изолированными юнит-тестами на базе сверхбыстрого фреймворка **Vitest**.

Для запуска тестов выполните в папке `client`:
```bash
cd client
npx vitest run
```

## 🤖 AI в разработке (Обязательный раздел по ТЗ)

При разработке дашборда использовался ИИ в качестве Senior-напарника (Pair Programmer) для выстраивания чистой архитектуры и ускорения написания шаблонного кода.

### Что было сгенерировано ИИ:
1.  **Архитектурный шаблон бэкенда:** Разделение папок Go на `cmd` и `internal` (`model`/`repository`/`service`/`handler`) по стандартам Clean Architecture.
2.  **Шаблон рекурсивного рендеринга дерева:** Написание заготовки рекурсивного вызова `TreeNodeItem` в React для отрисовки дерева неограниченной вложенности.
3.  **Базовые стили SCSS Modules:** Первоначальная верстка макета, цветовые схемы перформанса и адаптивная сетка Split-View на flex/grid.
4.  **Скелет мок-генератора:** Инициализация списка названий дивизионов, отделов и команд для наполнения базы данных.

### Что было переписано руками и доработано в паре с разработчиком:
1.  **Оптимизация рекурсивного SQL-соединения:** Первоначально ИИ предлагал рассчитывать показатели в PostgreSQL через рекурсивные CTE. Решение было полностью переписано: агрегация перенесена на клиент (In-Memory DFS), а бэкенд переделан под плоский Adjacency List. Это снизило нагрузку на СУБД до $O(1)$ на чтение/запись и уменьшило размер WS-патча до 110 байт (см. `docs/adr/001...`).
2.  **Уход от устаревшего `baseUrl` в TypeScript:** При переходе на TS 6.0+ и строгий bundler-режим Vite выявилась несовместимость флага `"baseUrl": "."`. Флаг был удален вручную, а маппинг путей переделан под новые стандарты нативных алиасов.
3.  **Strict Type-Only Imports:** Внедрена ручная поддержка флага `"verbatimModuleSyntax": true`. Все импорты типов были переписаны на синтаксис `import type { ... }` для гарантированного вырезания типов из JS-бандла компилятором.
4.  **Связь Таблицы и Дерева (getAncestors):** Полностью вручную разработана и протестирована логика умной навигации. При клике на строку таблицы дерево автоматически раскрывает всю цепочку родителей выбранного узла, используя хелпер поиска предков, и фокусирует пользователя на элементе.
5.  **Логика экспоненциального Backoff и In-Place обновления кэша:** WebSocket-клиент был доработан вручную для предотвращения "двойных запросов". Кэш обновляется в памяти через `queryClient.setQueryData`, запуская цепную реакцию пересчета агрегатов без единого HTTP-запроса по сети.
