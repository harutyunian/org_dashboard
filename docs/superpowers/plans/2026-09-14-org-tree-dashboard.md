# Staff Pulse Dashboard — План реализации

> **Для агента:** ТРЕБУЕМЫЙ SUB-SKILL: Использование `superpowers:subagent-driven-development` или `superpowers:executing-plans` для пошаговой реализации плана. Шаги используют синтаксис чекбоксов (`- [ ]`) для отслеживания прогресса.

**Цель:** Создать масштабируемый интерактивный дашборд для мониторинга орг-структуры компании с иерархическим деревом, аналитической таблицей, live-обновлениями через WebSockets и базой данных PostgreSQL.

**Архитектура:** Чистая слоистая архитектура (Clean Layered Architecture) с разделением ответственности (SOLID). На бэкенде Go (Gin + pgx) с слоями Handler -> Service -> Repository -> DB. На фронтенде React (Vite + TS + SCSS) с слоями Components -> React Query Custom Hooks -> OrgService -> Axios Client.

**Стек:** Go (Gin, pgx, Gorilla WebSocket), React (Vite, TypeScript, React Query, Axios, SCSS Modules), PostgreSQL, Docker.

**Spec:** `staff_pulse_assignment.pdf`

## Глобальные ограничения
*   Бэкенд строго на **Golang** (используем фреймворк Gin).
*   База данных строго **PostgreSQL** (запуск в Docker Compose).
*   Фронтенд строго на **React + Vite + TypeScript**.
*   Для запросов: **Axios** + **React Query** (TanStack Query).
*   Стилизация: **SCSS Modules** (никаких inline CSS, никаких MUI/AntD).
*   Каждый этап завершается коммитом с тегом `step/N`.
*   Все изменения логики должны покрываться проверками и быть технически чистыми.

## Архитектура базы данных (Схема PostgreSQL)

Будет создана одна основная таблица `org_nodes` со следующей структурой:
```sql
CREATE TABLE org_nodes (
    id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    parent_id VARCHAR(50) REFERENCES org_nodes(id) ON DELETE SET NULL,
    headcount INT NOT NULL DEFAULT 0,
    budget NUMERIC(15, 2) NOT NULL DEFAULT 0.00,
    performance INT NOT NULL CHECK (performance >= 0 AND performance <= 100),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL
);
CREATE INDEX idx_org_nodes_parent_id ON org_nodes(parent_id);
```
