# Архитектура приложения Staff Pulse Dashboard

Данный документ описывает архитектуру системы мониторинга организационной структуры компании с разделением на слои, потоки данных от базы данных до пользовательского интерфейса, а также принципы SOLID, примененные при проектировании.

---

## 1. Общий обзор системы (High-Level Architecture)

Приложение спроектировано по принципу **слоистой чистой архитектуры (Clean Layered Architecture)** с жестким разделением обязанностей (Separation of Concerns).

```text
  [ Client (SPA React) ]                    [ Backend (Go Server) ]
+-------------------------+               +--------------------------+
|  UI View Components     |               |   HTTP / WS Handlers     | (Gin Controller)
|   (TreeView/TableView)  |               |  (HttpHandler/WSHandler) |
+------------+------------+               +------------+-------------+
             |                                         |
             v (React Hooks)                           v (Go Interfaces)
+-------------------------+               +--------------------------+
|  React Query / Cache    |               |      OrgService          | (Business Logic)
|  (useOrgTree/WebSocket) |               |     (OrgServiceImpl)     |
+------------+------------+               +------------+-------------+
             |                                         |
             v (Axios Clients)                         v (Go Interfaces)
+-------------------------+               +--------------------------+
|       OrgService        |               |      Repository          | (Storage Interface)
|     (SOLID Service)     |               |     (PostgresRepo)       |
+------------+------------+               +------------+-------------+
             | (HTTP / WS REST)                        |
             +-----------------------------------------+ (SQL driver)
                                                       v
                                               [ PostgreSQL DB ]
```

## 2. Архитектура бэкенда (Go)

Бэкенд написан на языке **Golang** (Go) с использованием высокопроизводительного роутера **Gin** и стандартного SQL-пула подключений. 

### Слои бэкенда:
1.  **Слой сущностей (`internal/model`):**
    *   Содержит структуру `OrgNode`, представляющую плоскую модель узла компании, полностью описывающую поля в СУБД и JSON-представление для фронтенда.
2.  **Слой репозитория (`internal/repository`):**
    *   Реализован в виде интерфейса `Repository` и его конкретной структуры `PostgresRepository`.
    *   Отвечает за непосредственные SQL-запросы к PostgreSQL: чтение всех узлов (`GetAllNodes`), точечное обновление (`UpdateNode`), массовое пакетное наполнение (`SeedNodes`).
    *   Абстрагирует вышележащие слои от деталей работы с конкретной СУБД (принцип инверсии зависимостей - DIP).
3.  **Слой бизнес-логики (`internal/service`):**
    *   Интерфейс `OrgService` и реализация `OrgServiceImpl`.
    *   Управляет авто-созданием схемы таблицы (миграцией), автоматическим начальным заполнением (seeding) в случае пустой базы данных (генерирует ровно 42 узла, удовлетворяя лимитам ТЗ).
4.  **Слой представления / хэндлеры (`internal/handler`):**
    *   `main.go`: Настройка CORS, логгеров, обработка паник. HTTP-роут `GET /api/org-tree`.
    *   `ws_handler.go`: WebSocket-сервер для поддержки live-соединений. Управляет картой активных подключений в потокобезопасном режиме (`sync.Mutex`). Содержит фоновую горутину с таймером, симулирующую случайные изменения показателей в PostgreSQL каждые 5 секунд и транслирующую эти изменения в виде патчей.

## 3. Архитектура фронтенда (React + TypeScript)

Фронтенд спроектирован как строго типизированное одностраничное приложение (SPA) со слоистым потоком данных.

### Слои фронтенда:
1.  **Сетевой слой / Клиент (`src/api/client.ts`):**
    *   Инициализирует инстанс `Axios` с настроенными таймаутами (10 секунд) и обработкой сетевых ошибок.
    *   Поддерживает проброс `AbortSignal` для автоматической отмены незавершенных сетевых запросов при размонтировании UI-компонентов (требование надежности).
2.  **Сервисный слой (`src/services/OrgService.ts`):**
    *   SOLID-класс `OrgService`, инкапсулирующий вызовы сетевых эндпоинтов. Избавляет UI от знаний о путях эндпоинтов и методах запросов.
3.  **Слой кэширования и реактивных данных (`src/hooks/`):**
    *   `useOrgTree.ts`: Интегрирует `@tanstack/react-query` (TanStack Query) для декларативного кэширования данных. Задает `staleTime` в **5 секунд** согласно ТЗ.
    *   `useOrgWebSocket.ts`: Поддерживает WebSocket-соединение с автоматическим переподключением с **экспоненциальной задержкой (Exponential Backoff)**. При получении live-патча производит **точечное обновление локального кэша React Query в памяти «на лету»** без повторных HTTP-запросов по сети.
4.  **Слой утилит и обработки (`src/utils/`):**
    *   `tree.ts`: Алгоритм DFS сборки дерева из плоского массива за линейное время $O(N)$ с управлением состоянием раскрытия веток.
    *   `aggregation.ts`: Алгоритм пост-фиксного обхода дерева для инкрементального расчета суммарных бюджетов, сотрудников и средневзвешенной эффективности.
5.  **Слой интерфейса (`src/components/` & `App.tsx`):**
    *   Компоненты `TreeView` (интерактивное дерево) и `TableView` (аналитическая таблица).
    *   Поддержка темной/светлой дизайн-системы через SCSS Variables, адаптивный Split-View макет на экранах `>= 1280px` и вкладки на меньших экранах.
    *   Плавная анимация вспышки обновлений ячеек `.rowFlash` (fade-out за 1.5 сек).
    *   Полная клавиатурная навигация по таблице стрелочками, клавишами Home/End и Enter.

## 4. Схема потоков данных (Data Flow)

### Схема начальной загрузки данных:
```text
[ PostgreSQL ] --(SQL)--> [ PostgresRepo ] --(Go Struct)--> [ OrgService ] 
                                                                  |
                                                               (REST)
                                                                  v
[ App.tsx ] <--(useMemo Tree)-- [ useOrgTree ] <--(Axios)-- [ OrgService (TS) ]
```

### Схема Live-обновления в реальном времени:
```text
1. Go-Бэкенд (Горутина-таймер):
   [Timer 5s] --> [Modifies random Team] --> [Updates DB Postgres] --> [Broadcasts JSON WS Patch]

2. React-Фронтенд (useOrgWebSocket):
   [WS Message received] 
          |
          +--> [recentUpdates (Flashes cell 1.5s)]
          |
          +--> [Updates Query Cache in-place] 
                     |
                     v (Triggers reactive update)
               [useAggregatedData (Memoized recalculation only ancestors)]
                     |
                     v
               [App.tsx (Re-renders UI smoothly)]
```
